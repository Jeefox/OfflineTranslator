# Офлайн Переводчик EN ↔ RU

**OfflineTranslator** — десктопное приложение для перевода между английским и русским языками, которое работает **полностью локально**: весь перевод выполняется на вашей машине, без интернета, API-ключей и отправки текста на сторонние серверы.

В приложении два translation-бэкенда:

- **MarianMT** (Helsinki-NLP opus-mt) — по одной модели на направление (EN→RU и RU→EN), работает через `transformers`/`torch` на CPU или CUDA;
- **GGUF** (llama.cpp) — многоязычная модель `tencent/Hy-MT2-1.8B` через `llama-cpp-python` (CPU).

Плюс локальный словарь терминов (`dictionary.json`), который имеет приоритет над нейросетью.

## Возможности

- 🌐 **Двусторонний перевод EN↔RU** — выпадающий список «EN → RU» / «RU → EN» и кнопка «Сменить местами» (меняет поля, направление — и при необходимости модель).
- 🧠 **Выбор модели** — в «Настройках» доступны три модели: Marian EN→RU, Marian RU→EN и Hy-MT2 1.8B (GGUF). Приложение показывает локальную доступность каждой модели (без её загрузки) и активную модель — в подзаголовке окна и в строке статуса.
- ✈️ **Полностью офлайн** — после первичной загрузки Marian-моделей и подключения GGUF-файла интернет не нужен.
- 📡 **Streaming-перевод** — результат появляется по предложениям, в статусе — прогресс текущего юнита («Перевод… (k/n)»).
- 🎯 **Подсветка пар «предложение ↔ перевод»** — во время перевода подсвечена последняя завершённая пара; hover/клик в любом из полей подсвечивает пару в обоих полях.
- ↔️ **Синхронная прокрутка** — двусторонняя синхронизация прокрутки полей ввода и перевода (включая Linux).
- ⚡ **Инкрементальный кэш перевода** — повторный перевод изменённого текста отправляет в модель только изменённые/новые предложения.
- ⏱️ **Автоперевод** — после остановки набора текста (debounce по умолчанию 1.5 с); новый перевод отменяет незавершённый предыдущий.
- 📖 **Локальный словарь терминов** (`dictionary.json`) — при **точном совпадении** всего введённого текста перевод берётся из словаря, а не из модели; словарь двунаправленный.
- ⚙️ **Настройки** — стартовое направление, модель, тёмная/светлая схема, автоперевод, debounce, задержка статуса «Перевод…», лимит длины текста (по умолчанию 5000 символов), фильтр кириллицы (автоопределение направления по написанию).
- ⌨️ **Горячие клавиши в окне**: `Ctrl+Enter` — перевести, `Ctrl+L` — очистить поля, `Ctrl+,` — настройки, `Ctrl+C` в поле перевода — копирование, `Esc` — закрыть диалог.
- 🖱️ **Глобальный хоткей** (опционально, `pynput`) — по умолчанию `Ctrl+Alt+T`: выделяете текст в любой программе, нажимаете хоткей — приложение ставит текст в исходное поле, определяет направление, запускает перевод и поднимает окно.
- 🔔 **Трей и уведомления** — закрытие окна крестиком сворачивает приложение в системный трей; перевод из глобального хоткея приходит системным уведомлением. В настройках задаётся время жизни уведомления.
- 💬 **Понятные сообщения** — ошибки и статусы не содержат внутренних идентификаторов моделей, имён модулей и stack trace.
- 🖥️ **Интерфейс** на [CustomTkinter](https://github.com/TomSchimansky/CustomTkinter): тёмная/светлая схема, перенос длинных строк по ширине, копирование перевода в один клик, кнопка «Перевести» отключена на время загрузки модели.

## Модели и бэкенды

| Модель (id) | Направление | Бэкенд | Runtime | Откуда берётся |
| --- | --- | --- | --- | --- |
| Marian EN→RU (`marian-en-ru`) | en→ru | `marian` | `transformers` + `torch` (CPU/CUDA) | `Helsinki-NLP/opus-mt-en-ru`, входит в релизный бандль |
| Marian RU→EN (`marian-ru-en`) | ru→en | `marian` | `transformers` + `torch` (CPU/CUDA) | `Helsinki-NLP/opus-mt-ru-en`, входит в релизный бандль |
| Hy-MT2 1.8B (`hy-mt2-1.8b`) | en→ru, ru→en | `llama_cpp` (GGUF) | `llama-cpp-python` (только CPU) | **локальный `.gguf`-файл**, скачивания нет |

**Marian.** В готовой сборке обе базовые модели входят во встроенный кэш, поэтому приложение работает уже при первом запуске без интернета. Если запускать из исходников или выбрать модель, которой нет в локальном кэше, backend может скачать её с HuggingFace Hub при наличии интернета и сохранить в **постоянной директории пользователя**. После этого работа полностью офлайн.

**GGUF (Hy-MT2 1.8B).** Модель **не скачивается автоматически**: используется локальный файл (например, `Hy-MT2-1.8B-Q4_K_M.gguf`, ~1.1 ГБ, из репозитория `tencent/Hy-MT2-1.8B-GGUF` на HuggingFace). Путь задаётся переменной окружения `OFFLINE_TRANSLATOR_GGUF`. Бэкенд требует `llama-cpp-python` из `requirements-gguf.txt`; импорт ленивый — обычное приложение и Marian-путь работают без него. Работает только на CPU (POC-режим, контекст 4096).

**Выбор модели в приложении.** «Настройки» → «Модель» — список формируется из реестра моделей: видно имя модели, локальную доступность и пометку, если модель не поддерживает текущее направление. Выбор применяется по «Сохранить» **без перезапуска** (при необходимости модель перезагружается в фоне) и сохраняется в `settings.json`. Активная модель отображается в подзаголовке окна и в статусе «Готов к переводу! (Работает офлайн, модель: …)».

Если выбранная модель не поддерживает новое направление, приложение само переключает модель по умолчанию для этого направления с пояснительной заметкой в статусе. Если модель недоступна локально (например, не положен GGUF-файл), это видно в списке и в статусе — скачиваний и «черновых» исключений в интерфейсе нет.

## Установка

Требуется **Python 3.9+**.

```bash
# (рекомендуется) создайте виртуальное окружение
python -m venv .venv
# Windows:
.venv\Scripts\activate
# Linux/macOS:
source .venv/bin/activate

pip install -r requirements.txt
```

| Зависимость | Назначение | Нужна |
| --- | --- | --- |
| `customtkinter` | GUI | да |
| `transformers`, `torch` | Marian-бэкенд (CPU/CUDA) | да |
| `sentencepiece`, `sacremoses` | токенизация/предобработка для Marian | да |
| `pynput` | глобальный хоткей | да |
| `pystray`, `Pillow` | системный трей | да для поведения «свернуть по крестику» |
| `plyer` | уведомления Windows | fallback для Windows |

`llama-cpp-python` устанавливается отдельно из `requirements-gguf.txt` и нужен только для GGUF-модели. Для обычной Marian-сборки он не требуется.

Если нужен GGUF-бэкенд:

```bash
pip install -r requirements-gguf.txt
```

Требования глобального хоткея по платформам: **Linux (X11)** — дополнительно утилита `xclip` или `xsel` для чтения выделения; **Windows** — ничего extra. На Wayland агент может не запуститься — само приложение при этом работает как обычно (в статусе появится «Глобальный хоткей недоступен»).

## Запуск

```bash
python main.py
```

Дождитесь в строке статуса сообщения **«Готов к переводу! (Работает офлайн, модель: …)»** — модель загружается в фоновом потоке и не блокирует окно; на время загрузки кнопка «Перевести» отключена.

### Подключение GGUF-модели

1. Скачайте файл, например `Hy-MT2-1.8B-Q4_K_M.gguf` (~1.1 ГБ), из репозитория `tencent/Hy-MT2-1.8B-GGUF` на HuggingFace.
2. Укажите путь переменной окружения:

   ```bash
   export OFFLINE_TRANSLATOR_GGUF=/path/to/Hy-MT2-1.8B-Q4_K_M.gguf
   ```

   (Windows: `set OFFLINE_TRANSLATOR_GGUF=D:\models\Hy-MT2-1.8B-Q4_K_M.gguf`)
3. В приложении: **Настройки → «Модель» → Hy-MT2 1.8B (GGUF) → «Сохранить»**.

Если файл отсутствует (или не задана `OFFLINE_TRANSLATOR_GGUF`), модель в списке будет помечена как недоступная — приложение продолжит работать на встроенных Marian-моделях.

## Файлы и переменные окружения

| Данные | Windows | Linux/macOS |
| --- | --- | --- |
| Настройки (`settings.json`) | `%LOCALAPPDATA%\OfflineTranslator\settings.json` | `$XDG_CACHE_HOME/OfflineTranslator/settings.json` (по умолчанию `~/.cache/OfflineTranslator/settings.json`) |
| Кэш Marian-моделей (структура HuggingFace) | `%LOCALAPPDATA%\OfflineTranslator\cache` | `$XDG_CACHE_HOME/OfflineTranslator/cache` |
| Словарь в EXE-режиме | `%LOCALAPPDATA%\OfflineTranslator\dictionary.json` | user-директория (при первом запуске копируется из бандла, существующий словарь не перезаписывается) |

В development-режиме (`python main.py`) словарь читается из `dictionary.json` в корне проекта. Кэш моделей хранится **вне** рабочей директории — удаление кэш-папки приведёт к повторному скачиванию Marian-моделей при следующем запуске.

Переменные окружения:

- `OFFLINE_TRANSLATOR_GGUF` — путь к локальному GGUF-файлу (нужна для Hy-MT2-модели; используется также benchmark и smoke-тестом);
- `OFFLINE_TRANSLATE_CONFIG` — путь к `settings.json` (к файлу или к каталогу; удобно для тестов).

## Как работает перевод

1. **Словарь** — сначала проверяется точное совпадение всего введённого текста (регистронезависимо). Если в `dictionary.json` есть пара, перевод возвращается из словаря и модель не вызывается — поэтому закреплённые термины всегда актуальны.
2. **Пайплайн предложений** — текст разбивается на логические юниты (предложения, границы абзацев). Длинные предложения автоматически разбиваются на чанки, укладывающиеся в лимит входных токенов модели (для Marian — 480 токенов: лимит модели 512 минус запас); у GGUF лимит задаётся токенизатором и контекстом модели.
3. **Инкрементальный кэш** — перевод каждого юнита кэшируется в памяти под ключом **(модель, направление, текст юнита)**. Повторный перевод слегка изменённого текста (например, автоперевод при правке) отправляет в модель только изменённые/новые юниты; позиции предложений в ключ не входят, так что вставка/удаление других предложений не сбивает кэш. Кэш только в памяти: при перезапуске приложения и при смене модели он пуст. Результат одной модели/направления не используется для другой; словарь, как и в п. 1, проверяется до кэша.
4. **Бэкенд** — Marian: `model.generate` (beam search, 4 луча); GGUF: completion с модельно-специфичным промптом и явным направлением.
5. **Сборка и streaming** — юниты собираются обратно в результат (предложения внутри абзаца — пробелом, абзацы — пустой строкой). В streaming-режиме завершённые юниты по мере готовности появляются в поле перевода, статус показывает текущий юнит («Перевод… (k/n)»); попадания из кэша выдаются сразу, без вызова модели.

## Настройки и интерфейс

Основное окно: поле ввода, поле перевода, выпадающий список направления («EN → RU» / «RU → EN»), кнопка «Сменить местами», кнопка «Перевести», строка статуса. Окно настроек открывается кнопкой в шапке или `Ctrl+,`.

Изменения настроек применяются по «Сохранить» **без перезапуска**: тема, направление, модель (с фоновой перезагрузкой при необходимости), параметры автоперевода, глобальный хоткей. Невалидные значения не сохраняются — об этом сообщается в окне настроек.

Настройки хранятся в `settings.json` (путь — см. выше). Ключи и значения по умолчанию:

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `source_lang` / `target_lang` | `en` / `ru` | стартовое направление |
| `model_id` | не задан (авто) | выбранная модель: `marian-en-ru`, `marian-ru-en` или `hy-mt2-1.8b` |
| `theme` | `dark` | тёмная/светлая схема |
| `autotranslate` | `true` | автоперевод после остановки набора |
| `debounce_sec` | `1.5` | пауза ввода перед автопереводом, сек. |
| `slow_after_sec` | `3` | задержка показа статуса «Перевод…», сек. (0 — сразу) |
| `notification_duration_sec` | `5` | время жизни системного уведомления с переводом, сек. |
| `max_text_length` | `5000` | лимит символов (0 — без лимита) |
| `filter_cyrillic` | `true` | автоопределение направления по кириллице |
| `hotkey` | `ctrl+alt+t` | глобальный хоткей (записывается в окне настроек) |

Если в `settings.json` окажется неизвестный/невалидный `model_id`, приложение откатится на модель по умолчанию для текущего направления и пересохранит файл.

## Формат словаря

Словарь хранится в `dictionary.json` в flat-формате «ключ → перевод»; логическая пара записывается двумя зеркальными записями:

```json
{
    "workspace": "рабочее пространство",
    "repository": "репозиторий",
    "рабочее пространство": "workspace",
    "репозиторий": "repository"
}
```

- Ключи нормализуются (`strip` + `lower`), значения — `strip` (регистр сохраняется); поиск регистронезависим.
- Словарь **двунаправленный**: пара находится и в направлении EN→RU, и в направлении RU→EN.
- Политика 1:1 — у термина ровно один партнёр (одновременно `car → «машина»` и `vehicle → «машина»` нельзя); зеркало той же пары конфликтом не считается.
- Словарь срабатывает только при **точном совпадении** всего введённого текста.
- Изменения видны без перезапуска приложения (свежий snapshot читается перед каждым переводом).

## Benchmark

В `benchmarks/` — воспроизводимое сравнение бэкендов Marian и Hy-MT2 GGUF на фиксированном датасете из 200 примеров (100 EN→RU + 100 RU→EN, 12 категорий): latency (avg/median/p95), память, структурные свойства (числа, URL, email, code-токены), детерминизм и streaming. Benchmark работает поверх production-API, «победителя» не выбирает — данные для оценки.

```bash
# Marian + (если задан) GGUF:
OFFLINE_TRANSLATOR_GGUF=/path/to/Hy-MT2-1.8B-Q4_K_M.gguf \
    python benchmarks/run_benchmark.py
```

Подробности — в `benchmarks/README.md`.

## Сборка автономного приложения

Для локальной сборки используется PyInstaller и формат `onedir`: рядом с запускаемым файлом лежит каталог `_internal` с зависимостями.

На Windows:

1. устанавливает `pyinstaller`;
2. очищает старые артефакты сборки;
3. скачивает обе Marian-модели в локальный кэш;
4. собирает автономный бандль.

```bat
build.bat
```

Для Linux/macOS используется тот же `python build.py`; перед запуском должны быть установлены зависимости из `requirements.txt`. Релизный workflow GitHub Actions автоматически скачивает обе модели, собирает три платформенных бандля и прикрепляет их к GitHub Release.

Релиз создаётся после публикации тега вида `v1.0.0`:

```bash
git checkout main
git pull origin main
git tag v1.0.0
git push origin v1.0.0
```

В релизе появятся:

- `OfflineTranslator-Linux.tar.gz` — Linux x86_64;
- `OfflineTranslator-macOS.tar.gz` — macOS arm64;
- `OfflineTranslator-Windows.zip` — Windows x86_64.

## Ограничения текущей версии

- Поддерживаются только направления **EN↔RU** (реестр моделей готов к добавлению новых моделей/направлений).
- GGUF-бэкенд — **только CPU**, одна фиксированная модель (Hy-MT2 1.8B, POC-параметры: контекст 4096); модель **не скачивается автоматически**.
- Кэш перевода — **только в памяти**: после перезапуска приложения повторный перевод того же текста будет выполнен заново.
- Релизная сборка содержит обе базовые Marian-модели и запускается офлайн. При сборке из исходников `build.py` требует предварительно заполненный HF-кэш.
- Глобальный хоткей — опциональный: нужен `pynput`; на Linux — X11 и `xclip`/`xsel`; на Wayland может не работать (приложение при этом не страдает).
- Трей зависит от `pystray` и поддержки системного desktop-трея; уведомления используют `notify-send` на Linux, системный механизм macOS или `plyer` на Windows.
- Словарь срабатывает только при **точном совпадении** всего введённого текста — подстановки терминов внутри предложения нет.
- Одно окно с одной парой «ввод/перевод»; перевода файлов нет (см. дорожную карту).
