## Проверки

Пункт 1: torch обновлён в .venv до 2.10.0+cpu; tiny Marian успешно
загрузил safetensors и выполнил реальную генерацию при наличии
невалидного .bin. Проверены обе реальные Helsinki-модели на CPU офлайн
и ZIP без pickle. 18 наборов прошли после обновления двух GUI-фикстур.

Пункт 2: общий валидатор используется реестром, backend, настройками и
упаковщиком. Проверяет Marian config, JSON токенизатора, source/target SPM,
отдельный target vocab при необходимости и наличие всех safetensors shards.
Реестр и backend выбирают один и тот же полный локальный snapshot.
Проверки: 6 тестов валидатора, safe-model inference, registry, release models,
GUI stage10 (68 проверок), stage14 (71), UI review. Реальные подготовленные
Helsinki snapshots проходят валидатор. Проверка GPU не выполнялась.

Пункт 3: ошибки привязаны к (model_id, нормализованным путям нужных
направлений). Рабочий runtime A сохраняется при ошибке B; настройки
различают готовую модель и неудачную новую конфигурацию. Успех снимает
ошибку только для того же источника. GUI lifecycle, stage10/14 и UI review
проверяют откат, stale события и выбор совместимой модели.

Пункт 4: ModelLoader ловит исключения задачи и failure_callback,
продолжает обрабатывать очередь, предоставляет is_alive и результат submit.

Пункты 5–6: CancellationToken проверяется перед юнитом, до/после чанка и
перед кэшированием. GUI связывает отмену с поколением. TranslationChunk
хранит разделители; точные исходные чанки собираются без добавленного
пробела внутри длинного слова. Тесты проверяют отмену без cache/done и
многопробельные, tab, CRLF границы.

Пункты 7–8: защищённые фрагменты заменяются уникальными короткими числами;
переводится вся фраза, затем маркеры проверяются и восстанавливаются.
Буквенные XML-подобные маркеры и длинные числа реальная Marian повреждала,
поэтому они не используются. При пропавшем/дублированном маркере API
завершается ошибкой без кэширования. URL-пунктуация остаётся в контексте;
сбалансированные скобки внутри URL сохраняются. Реальная Marian успешно
перевела фразы с URL, email и кодом; качество не оценивалось численно.

Пункты 9–12: одиночные и Shift-only глобальные клавиши запрещены; clipboard
сохраняет края текста и CRLF (Windows проверен mock, Linux mock + GUI);
settings.save пишет через временный файл, fsync, replace и возвращает bool.
При ошибке GUI откатывает настройки в памяти, остаётся открыт и показывает
ошибку. Hover cache сравнивает исходный текст, а не его длину.

Пункты 13–15: Marian использует независимые лимиты направлений; load
публикует все модели/лимиты/устройство только после полного успеха;
max_new_tokens настраивается отдельно и ограничивается decoder positions.
Проверены разные config (512/1024), первая/повторная частичная ошибка,
ограничение генерации и настоящий tiny safetensors inference на CPU.

Полный прогон после пунктов 3–15: 23 standalone-набора через Xvfb, exit 0.
Файл локального журнала: /tmp/round2-points3-15-all.log.

Пункт 16: llama-cpp-python обновлён до 0.3.36; pip check прошёл. README
содержит правило доверенных источников и пределы текущего native runtime
(внутрипроцессный запуск, без sandbox). Официальная Tencent Hy-MT2 GGUF:
revision a0c709d9fac510f2c807aa3af52872340dc37a4a,
SHA256 dc5f44fcf1fa496ee7ad725982c0c8c553a4de00259b53af84c4b89fb0c06699
проверен после загрузки. Реальный smoke прошёл и повторён после финальных
изменений API. Benchmark: 24 заранее выбранных примера, все категории,
оба направления; 24/24 успешны, determinism 2/2, streaming 2/2.
Это подвыборка, не полный прогон 200 примеров и не сравнение качества.
Результаты: benchmarks/results/round2_gguf_runtime_0.3.36.json.

Пункты 17–21: PR smoke build Windows/Linux после tests; все внешние Actions
закреплены полными SHA проверенных официальных релизов Node24. Установка
моделей использует requirements-release.txt, исправлена склейка pip-команд
в YAML. Tests, PR build, release build и GGUF build на Linux используют
один composite action с проверкой создания Tk-окна. README: поддерживаемая
Python 3.12. Workflow прошёл actionlint 1.7.12. Windows/macOS jobs локально
не запускались; их выполнение проверяется на GitHub runners.

Пункты 22–24: tray CREATED/STARTING/READY/FAILED/STOPPED; READY выставляется
после native setup и установки visible. Timeout, ошибки и stale setup
не активируют трей; X11 без меню отключается, ошибка latin-1 в Xvfb исчезла.
Notifier проверяет exit status/timeout в фоне; ошибка возвращает скрытое
окно через GUI queue. Typed errors сохраняют __cause__, GUI использует
безопасные сообщения и полный диагностический лог. Benchmark записывает
исключение API в failed sample и продолжает остальные примеры; число чанков
считает после masking.

Пункт 25: per-unit Future делит результат или ошибку текущего inference,
включая результат, не помещённый в LRU. Backend обращения разных ключей
сериализуются. Отмена потребителя не отменяет владельца; при отмене
владельца независимый потребитель повторяет запрос. Проверены shared
success/failure, обе разновидности cancellation и отсутствие overlap.
Один backend не следует вручную разделять между разными service instances.

Финальная проверка: 27 standalone-наборов через Xvfb, exit 0
(/tmp/round2-final-all.log). После правки benchmark-runner его набор
повторно прошёл (/tmp/round2-final-benchmark.log). Также прошли compileall,
pip check, git diff --check, actionlint и финальный реальный GGUF smoke.
GPU и нативные Windows/macOS интерфейсы не проверялись.
